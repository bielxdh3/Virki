### A17 BFCache diagnosis through 2026-10-21

**Verdict recorded on 2026-10-20 (superseded by the 2026-10-21 follow-up below): `A17_PARTIAL_CAUSE_UNPROVEN`.** The earlier Playwright runs did not test BFCache eligibility of the authenticated Hub page. The installed Playwright 1.63 API documents that BFCache testing is unsupported, that Playwright disables BFCache by default, and that its page navigation state can desynchronize if BFCache is explicitly enabled. The installed Chromium argument list includes `--disable-back-forward-cache`. See the [Playwright Page API](https://playwright.dev/docs/api/class-page) and the local [Playwright 1.63 type declaration](../node_modules/playwright-core/types/types.d.ts). The previous harness diagnosis explains why its earlier `persisted=false` results were not product evidence; it does not establish why the actual authenticated Hub document does or does not restore.

The one-off raw CDP control used pinned Chrome 153.0.8010.12 and two same-origin local HTTP pages. Full Chrome without the Playwright switch restored both a public cacheable page and a private no-store page with pagehide.persisted=true and pageshow.persisted=true on the same document. Full Chrome with --disable-back-forward-cache restored neither. The chrome-headless-shell executable used by the official isolated runner restored neither the cacheable nor no-store control; its reason API returned masked, which does not identify the blocker. The reproducible script and captured results are in ignored local evidence at .virki-mission-tmp/isolated-runs/a17-bfcache-diagnosis-2026-10-20/.

The actual production-mode Hub E2E response for the ADMIN connections document was captured in run 354e694fda. Its Cache-Control was private, no-store, max-age=0, must-revalidate; its Permissions-Policy denied camera, geolocation, and microphone; its HSTS was max-age=31536000; its CSP was nonce-redacted in the log. Creation and rotation both scrubbed the secret on pagehide and left no secret in the DOM or accessibility after Back. Both reported persisted=false under the official Playwright/headless-shell harness.

Chrome allows some no-store pages into BFCache when safe, but cookie changes and no-store fetch/XHR responses remain relevant eviction conditions; the [Chrome no-store BFCache guide](https://developer.chrome.com/docs/web-platform/bfcache-ccns/) describes those conditions. The earlier minimal controls did not prove the authenticated Virki page eligible. Chrome's [notRestoredReasons guide](https://developer.chrome.com/docs/web-platform/bfcache-notrestoredreasons/) says null is not evidence either way. Do not weaken the protected no-store policy. A17 remains partial until both authentic flows show a persisted restoration of the original document and no recoverable secret, or direct app-specific evidence explains why restoration is unavailable.
