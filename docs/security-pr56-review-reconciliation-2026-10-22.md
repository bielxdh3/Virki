## Findings verified rather than assumed

- `packages/auth/src/csrf.ts` was classified as binary by Git because the earlier blob held literal NUL bytes inside the HMAC domain-separation string. `git diff --text` shows they became textual `\0` escape sequences; the runtime separator bytes are preserved. The current checkout contains no literal NUL or BOM in that file. This is not evidence of a bypass.
- `requiresRecoveryRequestSwitch` already exists in `apps/hub/src/lib/recovery.ts` in the reviewed base; its two imports from `recover/open/route.ts` have been consolidated. It was not an unresolved export.
- `scripts/lib/offline-release-attestation.mjs` already requires `Number.isSafeInteger` for canonical manifest `issued_at` and `expires_at`. Manual approval now repeats these checks as defense in depth. Both signing primitives now require a genuine Ed25519 private `KeyObject`.
- Shortened GCM tag rejection was already tested in `packages/auth/src/email.test.ts` and `packages/auth/src/oidc-secrets.test.ts`, not just TOTP. `authTagLength: 16` is implemented in all three relevant decryptors. Broader AAD and data-format work remains distinct.
- `lockAdminSessionInTransaction` already verifies ADMIN role, account activation, status, session revocation and expiry. The initial credential-setup path now obtains that lock inside the transaction too. A null `credentialKeyVersion` is legitimate **only** during first credential setup, before a credential exists; other elevation scopes reject missing or invalid versions. The additive database migration must precede application rollout, and old pending ceremonies without a version must be restarted (not implicitly upgraded).
- The public UserInfo endpoint previously placed valid bearer-token requests behind one anonymous per-IP 30-attempt bucket. A token digest now selects a separate untrusted per-token bucket; the existing per-IP ceiling remains. HEAD `/me`, POST `/session/end/confirm`, and provider case/trailing-slash aliases are now covered by rate-limiting/canonicalization checks.
- The rate-limit storage failure remains fail-closed at HTTP 503 and now emits a fixed, throttled operational diagnostic without bearer tokens, addresses, database errors or session data. Interaction `SessionNotFound` remains 400; unknown storage/provider lookup exceptions return generic 503. A native interaction completion exception before headers now has an HTTP regression confirming bounded failure, issuer security headers and `no-store`.
- In `.github/workflows/ci.yml`, both `sudo node --test` steps have an explicit GitHub-hosted/Linux/exact-repository guard. The unprivileged and root-only fixtures remain separate; no hosted CI check is bypassed.
- A subsequent real disposable Docker/Node 22 audit found a critical Next.js 16.3.8 advisory in the previously locked tree (npm GHSA-2464-fhr4-w9xw, GHSA-p3m5-59mp-jv5r, GHSA-673q-mjm6-r5xr). Both application packages and their exact-version root override now select Next.js 16.4.2, with the npm lockfile updated. The targeted local npm audit after reinstall returned zero vulnerabilities; this does not substitute for future registry advisories or a hosted audit at the accepted SHA.
