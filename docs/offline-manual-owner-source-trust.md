# Owner-installed manual source-SHA verifier (W32; not installed)

**Status: source-verifier prototype, READ-ONLY, NOT DEPLOYABLE.** The hosted
`main` / `origin/main` checks are unchanged. This file documents the proposed
independent owner installation; **do not copy a candidate's trust files into
the host, use test signatures as approvals or change `main` to enable a PR.**

Target example: PR #86 source commit
`c3ea768956bc3522363b725c138086a3c3e1c399`. This SHA is **not**
authorized by the repository or by this documentation. Only a separately
authenticated, explicit owner approval AND independent root-owned commit
pin can authorize its *source verification*. The actual approved CI branch
must come from verifiable runner evidence, never guessed from the PR number.

## Installed-only trust contract

An independently audited, root-installed native Linux/amd64 Node 22 closure
would use the fixed code path
`/usr/local/lib/virki/offline-release/infra/offline/trusted-manual-source.mjs`.
Its entry point accepts **only** `{candidateDirectory}`. No candidate,
request, env var or manifest can provide a key, pin, policy, trust directory,
counter, Git store or system clock.

An owner/operator **outside the release process** must separately install:

- `/etc/virki/manual-source` — root:root 0700, exactly three root:root
  0600 regular files, no links:
  `owner-key.json`, `approval.json`, `counter.json`.
- `/etc/virki/manual-source-owner.spki.sha256` — root:root 0600 or 0400,
  independently authenticated 64-character lowercase SHA-256 of the owner's
  Ed25519 public key SPKI DER followed by one newline.
- `/etc/virki/manual-source-commit.sha` — root:root 0600 or 0400,
  independently approved full Git SHA (e.g. PR #86 SHA above) plus newline.
- `/var/lib/virki/offline-source/trusted.git` — preinstalled independent,
  root:root 0700 bare Git store, complete audited objects for the approved
  commit, with no remote fetch, alternates, replacement refs, unsafe modes or
  hooks. **Its `main` stays at its previous SHA**. The manual verifier
  authenticates the exact signed commit object and every source TAR blob
  without requiring a branch tip.

The owner must authenticate and pin the independently audited *entire native
verifier code closure* (including imported source parser and CI evidence
modules) through an owner-reviewed installation/upgrade. Merely changing
repository files does not update the installed verifier. Existing installer
and hosted coordinator are **not changed** here.

The three canonical JSON documents (serialized by `JSON.stringify`, exact
field order, no whitespace) are:

| File | Required object fields, in order |
| --- | --- |
| `owner-key.json` | `version=1`, `keyId`, `publicKeyPem` |
| `counter.json` | `version=1`, `lastAcceptedSequence`, `approvedSequence`, `revokedKeyIds`, `revokedPinsSha256` |
| `approval.json` | `document`, `signatureBase64` |

The **document** within `approval.json` is canonical JSON with exactly:
`version=1`, `mode="owner-manual-source-sha-v1"`,
`repository="https://github.com/bielxdh3/Virki.git"`, `sourceSha`,
`ciSourceBranch`, `sourceArchiveSha256`, `ciReportSha256`,
`runtimeImageId`, `migratorImageId`, `hostIdentitySha256`,
`sequence`, `validFromSeconds`, `validUntilSeconds` (in this order).
The Ed25519 owner signature covers the exact bytes:
`UTF8("VIRKI_MANUAL_ROOT_SOURCE_APPROVAL_V1\\0") || UTF8(JSON.stringify(document))`.
The signature is canonical 64-byte Ed25519 Base64. No private key is stored
with the candidate or generated by the host verifier.

The owner's signature and **separate** host pins must agree on the commit.
All archive/CI digests, immutable runtime and migrator image IDs, host
identity and the exact non-`main` CI branch must agree with the inspected
candidate. `validUntilSeconds > validFromSeconds`, at most 24 hours apart;
the native verifier uses its local clock. The independently protected counter
requires `sequence == approvedSequence == lastAcceptedSequence + 1`.
Revoked owner key IDs and public-key pins fail closed.

**Counter limitation:** this is a read-only *anti-rollback floor for
preauthorized inspection*, **not** an atomic consumption mechanism. The
operator must advance and durably protect `lastAcceptedSequence` in an
independent acceptance transaction. Replaying a valid source-preview request
before that transaction remains possible; it produces **no approval token**
and **never deploys**. Native clock authenticity, anti-replay/remote
monotonicity, independent 19-stage CI runner provenance, full signed release
manifest, ledger, scanner, restore/rollback checks and actual deployment are
still separate mandatory gates.

## Safety boundary and test scope

`inspectManualOwnerApproval` is pure parsing/verification; its inputs do not
create a trust root. `inspectManualRootSourceForPreview` permits fixture-only
paths, but always returns `deployAuthorized:false`. Only
`verifyInstalledManualRootSource` hard-codes independently installed paths
and rejects WSL, non-root and uninstalled code. The installed path performs
an additional strict structural CI check for the owner-signed branch and SHA;
structural checks alone **do not establish runner provenance**.

Tests generate ephemeral Ed25519 signing keys and throwaway Git objects
**only in root-owned Linux test fixtures**. Those fixture approvals, image
identifiers and CI digests are not production material. No valid owner
approval or genuine 19-stage CI evidence was received. No host installation,
integration into the coordinator, source-main change, Docker load, remote
transfer, commit, push or deployment is authorized by this W32 change.

The native inspection also invokes the existing installed host verifier to
check the real machine-id against an independently installed release policy,
BOTH owner and builder signatures on the final canonical manifest, and the
actual Docker archives including immutable image IDs and exact OCI source
revisions. All of these gates are read-only; the real approvals and evidence
must exist before acceptance. A source permit cannot substitute for them.
