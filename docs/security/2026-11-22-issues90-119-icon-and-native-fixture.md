# Issues #90/#119 — public icon route and offline image-verifier proof

The previous exact-asset whitelist protected private extension-shaped routes but inadvertently required a session for Next App Router's real public metadata route `apps/hub/src/app/icon.svg` (served as `/icon.svg`). The whitelist now admits only the explicitly shipped `/hub-mark.svg` and `/icon.svg` on the relevant public/native surfaces. The existing Hub Cloudflare Access perimeter is still evaluated before the session exemption. Negative proxy tests continue to require authentication for `/admin/icon.svg`, `/account/icon.svg`, private `.js`, `.txt`, `.css` and related paths.

An independent source review reproduced the unexpected redirect. Focused `apps/hub/src/proxy.test.ts` **25/25 PASS** after the correction; no wildcard pathname or extension rule was restored.

The former native-only `trusted-host-entry.test.mjs` image-format test contained **no assertions on a supported kernel**, which could manufacture a pass without checking a TAR or trust boundary. It now executes an actual Linux negative: a syntactically consistent **UNTRUSTED_ENVELOPE_ONLY** with matching hashes is accepted for untrusted byte inspection, but the *same* runtime/migrator archives are rejected independently by `verifyOfflineDockerSaveTar`. This test exercises no signed release, image load, Docker daemon, production trust directory or network operation. Linux WSL `infra/offline/trusted-host-entry.test.mjs` **11/11 PASS, 0 SKIP**; the dedicated real native-host proof remains separately gated.

Full `test:production-revision` on Node22 Linux WSL after the change: **373 total, 359 PASS, 0 FAIL, 14 SKIP**. Three separately root-gated transport fail-closed tests also passed with WSL UID0. Remaining skips requiring an installed non-WSL native kernel/root authority are **not** represented as completed production security checks. Local lint, typecheck, Prisma and production build are independent build-readiness checks and do not authorize deployment.
