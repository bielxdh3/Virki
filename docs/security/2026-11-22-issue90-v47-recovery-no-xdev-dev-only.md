# Issue #90 — V47 DEV-only: recovery observation respects the publisher's mount boundary

V47 is an **additive defense-in-depth increment**, not a confirmed exploitable P1/P2 or a release feature. The root-only V38 read-only recovery observer previously used `openat2` with `RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS`, but omitted an *explicit* `RESOLVE_NO_XDEV` flag already required by V36 publication and V40 durable trust-root resolution. V38 never authorizes admission. Its prior independent V24 ancestor validation also rejected tested `/dev/shm` and `/tmp` mounted snapshots before this change, so a cross-mount **accepted observation was not reproduced**. The explicit syscall restriction now matches the publisher's path-custody contract even if earlier validation changes.

The V38 observer now opens **both its protected parent and final published-snapshot directory** with all four resolution constraints, including `RESOLVE_NO_XDEV`. Its existing ancestor ownership, mode, manifest, inode, hash and fsync checks remain unchanged. A new root-only opt-in Linux test performs a **positive** open of a protected directory on the same filesystem and a **negative** open across a real distinct filesystem, after first proving that the older resolution flags would have crossed that mount. A second test uses `unshare --mount --propagation private` to create a disposable same-device **bind mount on the final snapshot name**, with identical trusted bytes; an ordinary same-mount snapshot must still return `present-requires-owner-reauthorization`, but the bind-mounted alias must fail `EXDEV`. Both tests require positive control assertions and have no silent skip in the mandatory root fixture.

This change is contained in immutable incremental `docs/security/experiments/buildkit-v0.34.1-c1-v47-recovery-observer-no-xdev-dev-only.patch`, based on the V46 cumulative tree `4e8440c77a86e009685717e86194bb4e6a83ff81`. Patch SHA-256 `c411f76f15e0a73871030b264280cbb641e54f3faa829010c89957a26ab88465`; V47 cumulative tree `5de9120c20a35c8b0dee8a85e47973471759c315`. All V23–V46 patch bytes/hashes/trees remain unmodified. The replay index now checks **25/25 (V23–V47)**. CI's mandatory sudo `-race` fixture includes the opt-in `VIRKI_V47_RUN_ROOT_FIXTURE=1`, selects **both** tests and fails on any skip.

The two isolated V47 Go Linux root tests passed with `-race` before publication. An independent read-only Go-overlay proof confirmed the older full V38 inspector already returned errors for `/dev/shm` and `/tmp`, but also found **a real same-device bind alias** accepted as `present-requires-owner-reauthorization` with nil error when the mount target was the final snapshot component. Altered bytes were correctly rejected; no auto-admission occurred. V47 closes this provenance ambiguity at the syscall layer but remains defense-in-depth under a root-trusting DEV threat model, **not** a demonstrated release bypass. It provides **no** signed C4 owner approval, production authorization, external monotonic rollback witness, deployment or automatic owner reauthorization. C1/C4 remain disabled/NO-GO for production.
