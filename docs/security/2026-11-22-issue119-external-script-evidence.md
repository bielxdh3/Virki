# Issue #119 — CSP nonce-bearing external script is not execution evidence

An independent browser review identified a second static-classifier false PASS: a correctly nonced HTML `<script src="">`, `<script src=" ">`, or `<script src="/missing.js">` was treated as sufficient positive evidence of execution and therefore of a nonce CSP receipt. Chromium/Edge does not execute the inline body of a script containing `src`; empty/whitespace URLs or HTTP 404 resources may never execute at all. The prior helper checked the nonce but did not distinguish *inline* execution from an external network resource whose success had not been observed.

The bounded classifier now rejects empty/whitespace/missing-valued `src`, **still checks nonces on valid external scripts**, and requires **at least one executable inline script with a matching nonce** to return PASS. A correctly nonced external script alone is inconclusive and therefore FAIL under this strict receipt. This is deliberately conservative: a legitimate app relying exclusively on loaded external scripts must demonstrate execution with a real browser, rather than passing the HTTP-only classifier. An external script with an incorrect nonce remains a failure even when another valid inline script exists. No runtime CSP policy is weakened.

The new regression was first observed RED (`expected: fail`, `actual: pass`). After correction, all three offline #119 suites passed **33/33 with zero skips**, plus Node22 lint and secret scan. A previously built Next.js public-site production build was served on an isolated loopback port and its **real HTTP 200 and 404** responses both still passed the updated classifier (`htmlDocument=confirmed`, `scriptNonce=matched`, no `unsafe-inline`, no `X-Powered-By`); the local server was terminated. The independent reviewer also proved in Playwright/Edge that the inline control executes but the three `src` variants do not, with `/missing.js` actually returning 404.

This is a stronger **static receipt policy**, not browser hydration, authenticated origin acceptance, evidence of a deployed application SHA, or a Cloudflare configuration change. The live public deployment's previously observed CSP and `X-Powered-By` failures remain unresolved absent separately authorized deployment.
