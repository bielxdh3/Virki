## Highest-risk implementation paths and security reasoning

- **#15, #16, #17 — native image import.** Operator Docker CLI SHA-256 pin is independent, root-owned 0600; the binary is root-owned 0700, verified through O_NOFOLLOW and fstat, then invoked only against an isolated Docker socket. Authenticated uploads are copied from a pinned source FD to private exclusive quarantine (O_EXCL), rechecked by full TAR/sha256 parsing, unlinked and fed to Docker load by already pinned FD stdin. No pathname reopening at load, Docker tag, or deployment authority.
- **#9, #11-14, #19, #22-25, #30, #36 — trusted owner and host input.** Privileged entrypoints demand native Linux/root or owner-locked 0700 directories, private 0600 regular leaves, non-follow descriptors, before/after inode and metadata validation; pinned Git SHA and independently provisioned policy anchor trust. Machine-id is a bounded host identifier, not hardware attestation. Host root compromise is not claimed to be defended against.
- **#18, #27-29, #31-32, #37 — candidate TAR and report readers.** Validation and hashing use pinned original inode via FD or FileHandle, preserve size and content bounds, and double-check metadata or SHA-256. A mutable path is never the authority for independently trusted bytes; previews and unsigned bundle builds cannot authorize release.
- **#41-43 — finalization and trusted request.** Owner-private 0700 directory; source 0600 leaf read with O_NOFOLLOW and pre/post stat; reopens are pinned and rehashed, copied to O_EXCL 0600 private destination with digest/identity checks before atomic publication. Trusted request is separate from unsigned bundle and canonical JSON.
- **#0, #3-5 — TLS/URL/example.** Disabling TLS validation occurs only as a negative test that expects rejection, immediately deletes and restores env, and issues no network request during disabled state. URL/CSP cases assert exact-or-rejected values in tests. RP POST /login is intentionally public to *start* OIDC but guarded by encrypted TLS socket, exact Host, Origin/fetch-site/content-type checks and peer IP rate-limiting; it does not grant access or mint an authenticated session.
- **#20-21, #26, #33-35, #38-40, #44-45 — disposable tests.** Assertions read their own isolated fixtures and adversarial tests deliberately replace/truncate source paths to prove pinned-FD behavior. Such observations are never production release authority.
