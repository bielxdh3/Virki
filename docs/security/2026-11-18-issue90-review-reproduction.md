The last tree is the locally verified DEV source configuration. V30 fixes a helper pathname-to-exec swap through FD-pinned execution; V31 makes root-owner/immutable-ancestry checks **mandatory whenever root launches a distinct receiver UID**, even if the caller omits the optional policy flag. V32 requires the independent receiver to become non-dumpable after exec. V33 requires a separate **unprotected same-UID positive control** to prove ptrace attach and procfd inspection are possible on the host, then requires both operations to fail on a protected child under equivalent conditions. V34 pins all ptrace attach/wait/detach syscalls to one Linux thread with `runtime.LockOSThread` to avoid spurious `ESRCH` if Go reschedules the tracer goroutine. If positive controls are blocked by host policy, the mandatory test **fails as INCONCLUSIVE**, rather than claiming V32 works. V33 also re-inventories and re-hashes the pinned published stage inode after parent fsync: concurrent in-place mutation or injected file now returns the explicit **published but unadmitted** terminal error, avoiding an incorrect successful admission. **This does not prevent transient publication of malicious bytes or prevent later same-UID mutation.** The synthetic fixtures prove that a root-owned helper under a receiver-owned directory and a receiver-owned helper are refused; a trusted helper still runs. This package does not certify independently provisioned custody for an actual production lifetime, peer authentication of arbitrary transport endpoints, or production admission. The Linux multi-process fixture checks same-namespace rename/symlink/write/mount attempts from an independently unprivileged peer, but cannot prove every hostile mount configuration. Do not enable protected FileSync or deploy.

V35 pins the stage directory **before** receiving data and writes through its FD-rooted pathname, reopens the parent fsync handle relative to its already-pinned descriptor, rechecks destination inode identity after postcommit hashing, and independently checks that the requested absolute parent pathname still resolves to the pinned parent inode. Deterministic same-UID adversarial tests swap the stage during the receive callback, swap the final destination after postseal verification, substitute a symlink, and rename/replace the parent after parent fsync. These tests prevent observed false admissions but **do not prevent a same-UID process from substituting the stage between the last check and `renameat2`, modifying files after the final hash, or exposing untrusted bytes transiently**. Filename-based recursive cleanup is best effort and not safe as an independent adversarial custody guarantee. Only a separate trusted publication principal/namespace or truly inode-bound atomic mechanism can satisfy the outstanding production acceptance gate.

V36 adds an **unwired DEV reference implementation of a separate root-owned publication principal**. The trusted root broker takes an already-pinned source FD plus a separately authenticated frozen manifest/receiver UID, copies only manifest-approved regular source files with `openat2` no-follow under strict budgets to fresh root-owned inodes beneath a root-owned 0700 parent with protected ancestors, re-verifies the independent copy, fsyncs and performs no-replace atomic publication inside that protected directory. Tests prove a synthetic nonroot same-UID writer can mutate its own source but cannot change the root-owned published tree, exercise concurrent source writes and symlink escape denial, and reject preexisting destinations/untrusted parent paths. **The broker has no authenticated IPC/SCM_RIGHTS handoff or production caller and MUST NOT be considered deployed/accepted.** Until complete supervision, true peer authentication, durable authorization/recovery and independent release review exist, protected C1/C4 remain NO-GO.
