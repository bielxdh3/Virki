A read-only Firefox session reproduced the password-toggle failure on the public Portal page: click and keyboard activation left the password input masked and `aria-pressed=false`. The page's Next.js scripts arrived with Cloudflare Rocket Loader's rewritten script type, while the browser blocked `rocket-loader.min.js` under the existing nonce plus `strict-dynamic` CSP. This strongly indicates a Rocket Loader/CSP interaction preventing the client handler from running. The issue names release SHA `1a12ac6d4aa5689564d9a16cadc7361b981de3a8`; GitHub's latest `production` deployment record for that SHA is a failed attempt, so the live page's served SHA is not independently attested. A scoped Cloudflare rule to disable Rocket Loader while keeping CSP intact is the likely operational correction; no production configuration was changed. The X509Store helper's 15-second timeout covers the entire PowerShell subprocess and has no phase markers, so the available evidence does not isolate a stall inside `X509Store.Add`. The current Docker E2E path does not call it. The Windows CurrentUser Root still has the prior public E2E CA because automatic execution review rejected its exact-thumbprint removal; no CA was installed by the Docker runner. GitHub CI and CodeQL remain blocked before runner allocation by an account-payment/spending-limit annotation. Issues #43 and #45–#50 remain open. Only the public Portal page and GitHub metadata were read; no production host, database, deployment, secret, or configuration was modified.
